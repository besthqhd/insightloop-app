# Prompt 优化审计协议

目标不是把总分调高，而是降低可复核的字段误判，并校准模型何时应标为低置信。

## 固定规则

1. 保留当前真实模型运行产物作为基线；不覆盖、不删除低分错例。
2. 每轮只改一个 Prompt 变量，例如正/负情绪判定、混合情绪规则或置信度规则。
3. 每个 `×` 必须先归入以下一种原因：`模型误判`、`标签不清/错误`、`信息不足应 abstain`、`解析/调用失败`。
4. 不得因某条用例表现差而改写其期望标签；标签修订须人工复核并记录理由。
5. 「可行动代理通过率」不用于证明准确或有帮助；每轮同时报告字段命中率、置信度分布和人工复核结论。

## 一轮执行模板

1. 在评估看板运行真实模型，点击“导出审计结果”。
2. 从字段未命中的用例中按 App、语言、主题分层抽取 20–30 条，逐条记录 `expect`、`output`、原因与人工裁定。
3. 根据出现最多、且裁定为模型误判的单一原因，修改一条 Prompt 规则。
4. 用同一配置复跑；保留前后两份运行产物和 Git SHA。
5. 在未参与错例分析的用例上复测。若没有新的独立数据，必须标记为“同集回归检查”，不能称为泛化提升。

## 当前优先审计的问题

真实模型出现 `× / ✓`：字段未命中但置信度不低。先确认这些用例是否应为低置信，或评测标签是否需要人工修订；在结论明确前不调整阈值以追求更高分。
