审计来源：`insightloop-eval-audit-2026-09-03.json`，143 条公开竞品评论，模型为 `glm-4-flash`。该文件由浏览器导出；本报告不把汇总指标当作人工金标。

浏览器看板将字段命中率四舍五入为 57%，但导出 JSON 逐例汇总为 75 / 143（52.4%）。后续必须以可复算的逐例产物为准，并排查看板与导出文件是否来自同一次运行或存在展示/导出版本差异。

## 最主要发现：规则标签与文本语义不一致

68 条字段未命中中，51 条的期望情绪是 `neutral`；其中模型输出 `negative` 或 `angry` 的有 39 条。大量案例从文本看，模型的负面判断更符合常识：

- DeepSeek「服务器繁忙，服务不稳定。」：期望 `neutral`，模型 `negative`。
- 豆包「基础功能没打磨好就急着收费，本末倒置。」：期望 `neutral`，模型 `negative`。
- 元宝「数据统计出错……票数都数错。」：期望 `neutral`，模型 `negative`。
- Kimi「一个问题十分钟都出不来……啥垃圾玩意儿。」：期望 `neutral`，模型 `angry` 且触发风险升级。

这些不是应通过 Prompt 把模型“调回 neutral”的坏例。先修改标签或让人工裁定，才是正确修复路径。

## 次要发现：置信度被旧 Prompt 系统性抬高

旧规则要求“只要任一字段能判断，就不得 low”，导致 141 / 143 通过可行动代理；但 67 条同时字段未命中。该指标无法代表正确或可直接行动。

本次仅调整了 `confidence` 指令：把它定义为“能否仅凭该文本直接行动”，并要求纯表扬、纯辱骂、泛泛评价或信息冲突时标为 `low`。这是校准改动，不承诺提高字段命中率；它可能降低代理通过率，属于预期且更诚实的结果。

## 下一轮操作

1. 从 68 条未命中中按 App 与主题分层抽取 20–30 条，双人或至少人工复核，标记：`模型误判` / `标签问题` / `信息不足应 abstain` / `调用失败`。
2. 将确认错误的规则标签修订为独立人工金标，保留原规则标签与修订理由。
3. 仅针对“人工确认的模型误判”写一条 Prompt 规则；不要针对标签问题调 Prompt。
4. 固定模型、数据、其余 Prompt 与参数，复跑并保存产物。没有新的独立数据时，只能称“同集回归检查”，不能称泛化提升。
